# KIPRIS Plus 검색식 메모

> **검증 상태 표기**: ✅ 실제 호출로 확인 · ⚠️ KIPRIS 웹 검색 문법 기준, API에서 미확인.
> 새로 확인한 내용은 `docs/kipris-api-notes.md`에 날짜와 함께 남기고 이 표를 고쳐 주세요.

`park search --word "<검색식>"`의 `<검색식>`은 `freeSearchInfo`의 `word` 파라미터로 그대로 전달된다.

| 요소 | 예시 | 상태 |
|---|---|---|
| IPC | `IPC=[G06N]` | ✅ |
| 출원일 범위 | `AD=[20190101~20191231]` | ✅ |
| AND | `*` (예: `IPC=[G06N] * AD=[...]`) | ✅ |
| OR | `+` — 필드 안(`AB=[전자피부+인공피부]`)과 필드 사이(`TL=[촉각]+AB=[촉각]`) 모두 | ✅ 2026-11-09 |
| NOT | `!` | ⚠️ |
| 발명의 명칭 | `TL=[...]` | ✅ |
| 요약 | `AB=[...]` | ✅ |
| 청구범위 | `CL=[...]` | ✅ |
| 출원인 | `AP=[출원인명]` | ✅ |
| 괄호 묶기 | `(A+B)*C` | ✅ |
| 한 번에 받는 건수 | `docsCount` 500까지 | ✅ (호출 1회에 500건) |

### 실제로 확인한 동작 (2026-11-09, '촉각센서' 기준 건수)

| 검색식 | 건수 | 뜻 |
|---|---:|---|
| `촉각센서` (필드 없음) | 58,908 | 전문에서 낱말을 넓게 찾는다. **쓰지 말 것** |
| `"촉각센서"` | 459 | 큰따옴표: 구문에 가깝게 찾는다 |
| `TL=[촉각센서]` = `TL=[촉각]*TL=[센서]` | 227 | 필드 안의 복합어는 **낱말로 쪼개 AND** 한다 |
| `AB=[촉각센서]` | 618 | 요약 |
| `CL=[촉각센서]` | 2,021 | 청구항 — 넓다. 다른 조건과 AND 할 것 |
| `AB=[촉각]` | 2,594 | 한 낱말만 쓰면 넓어진다 |

복합어가 쪼개지므로 `AB=[인공피부]`는 '인공'과 '피부'가 따로 있어도 걸린다 (화장품·의료 문헌이 섞임). 이런 말은 `*(AB=[센서]+AB=[감지])`처럼 기술 조건을 AND로 붙인다.

## 검색식 설계 순서

1. **기술 분류표의 중분류마다** 핵심어와 동의어 묶음을 만든다 (한글, 영문 표기, 약어: "이차전지+2차전지+secondary battery+리튬이온").
2. 묶음끼리 `*`로 잇고, 너무 넓으면 IPC로 좁힌다. IPC는 *보조*로만 쓴다. IPC만으로 자르면 분류가 다르게 붙은 핵심특허를 놓친다.
3. **먼저 건수만 본다**: `park search --word "<식>" --count-only --out <dir>`는 호출 1회로 전체 건수를 알려 준다.
4. 건수가 수천 건이면 기간·IPC·키워드로 좁힐지, 그대로 모두 받을지 사용자와 정한다. 한 번에 100건씩 받으면 1,000건 = 호출 10회다.
5. **알려진 핵심특허로 재현율을 점검한다**: 사용자가 알고 있는 특허(또는 대표 기업의 대표 특허) 몇 건이 결과에 들어 있는지 확인한다. 빠졌다면 왜 빠졌는지(용어, IPC) 보고 검색식을 고친다.
