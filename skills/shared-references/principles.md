# PARK 공통 원칙 (모든 스킬이 먼저 읽는다)

1. **판단은 내가, 숫자는 도구가.** 건수·비율·순위는 직접 세거나 추정하지 않는다. 항상 `park` 명령의 결과(`map/stats.json`)를 쓴다. 보고서 문장에 숫자가 필요하면 `{{meta.n_counted}}` 같은 자리표시자를 쓴다. 사용자에게 진행 상황을 말하거나 `SCREENING.md` 같은 작업 기록에 적을 때는 `park` 출력이나 `stats.json`의 값을 그대로 옮겨 적어도 된다. 금지되는 것은 직접 세거나 어림하는 것이다.
2. **근거 없는 판정 금지.** 판정마다 `출원번호 + 위치(요약/청구항 n/[문단]) + 원문 그대로의 인용`을 단다. 인용은 원문에서 **복사**한다. 다듬거나 번역하지 않는다. `park check`가 인용문이 원문에 있는지 검사한다.
3. **근거 등급.** 요약·서지만 봤으면 `provisional`, 청구항·명세서 전문을 봤으면 `confirmed`.
4. **범위를 넘는 결론 금지.** KR 특허만 검색했다면 "KR 공개특허 동향"이다. "신규성이 있다", "공백기술이다", "침해하지 않는다"처럼 단정하지 않는다. 필요한 표현은 "검색 범위 안에서는 ~가 확인되지 않았다".
5. **미공개 구간.** 기준일 전 약 18개월의 출원은 덜 집계된다. 최근 연도 감소를 "감소 추세"라고 쓰지 않는다.
6. **체크포인트에서 멈춘다.** 기술 분류표, 검색식, 선별 결과를 확정하기 전에 사용자에게 보여 주고 확인을 받는다. 사용자가 자동 진행을 명시한 경우만 예외.
7. **API 호출을 아낀다.** KIPRIS Plus 무료 한도는 월 1,000회 *호출*이다. 검색 전에 `park quota`로 남은 횟수를 확인하고, 전체 건수만 먼저 볼 때는 `--count-only`를 쓴다.
8. **기밀.** 사용자가 준 기술 설명을 외부 모델(Codex 등)에 보낼 때는 먼저 허락을 받는다.
9. **면책.** 모든 산출물은 "검토 의견 초안이며 법률 의견이 아님"이다.

## 분석 폴더 (`analysis/<프로젝트>/`)

| 파일 | 만드는 쪽 | 내용 |
|---|---|---|
| `BRIEF.md` | park-pipeline | 과제 설명, 목적, 사용자 확인 기록 |
| `TECH_TREE.md` | tech-scoping | 기술 분류표 (첫 칸에 백틱 코드) |
| `QUERIES.md` | tech-scoping | 키워드, 동의어, IPC, 검색식 |
| `SEARCH_LOG.md` | park 도구 (+ 사람 메모) | 실제로 실행한 검색과 결과 수 |
| `candidates.csv` | park 도구 | 후보 문헌 |
| `screening/todo/*.md`, `screening/done/*.jsonl` | park 도구 / relevance-screening | 선별 작업 단위 |
| `screening.csv` | park 도구 (병합) | 선별 결과 |
| `map/stats.json`, `map/*.svg` | park 도구 | 집계와 차트 |
| `REPORT_NOTES.md` | park-report | 해석 문단 (숫자는 자리표시자) |
| `REPORT.html` | park 도구 | 최종 보고서 |

`park` 명령이 PATH에 없으면 저장소 루트에서 `python -m park`로 실행한다.
