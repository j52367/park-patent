# 실험: 사전 정렬 방식 비교 (2026-11-09)

**질문:** `park rank`의 글자 n-그램 TF-IDF 정렬을 한국어 임베딩 모델로 바꾸면 유효 문헌을 더 위로 모을 수 있을까?

## 데이터
- 실제 주제 하나에서 모은 KR 후보 7,124건.
- 라벨: PARK 선별 결과 2,125건 (유효 717 / 노이즈 1,408, 보류는 제외). 판정은 Codex, 근거 인용은 모두 원문과 대조했다.
- **꼬리 표본 175건:** 정렬 컷 아래에서 무작위로 뽑은 문헌이다. 어떤 정렬로도 고르지 않았으므로 편향이 없는 시험셋이다. 아래 표에서 이 열을 주 지표로 본다.
- 문서 텍스트: 명칭 + 요약.
- 장비: RTX 3090, fp16, 최대 512 토큰. 스크립트는 `experiments/embed_rank.py`.

('판정 학습'은 각 문헌을 그 문헌을 보지 않은 모델로 채점한 교차검증 점수다.)

## 해석
1. **분류표와의 유사도만으로는(학습 없이) 임베딩이 거의 이기지 못한다.** 분류표 한 줄은 짧고 추상적이어서, 문헌과 의미가 가까운지보다 "이 칸에 들어가는가"라는 판정 기준이 더 중요하기 때문으로 보인다.
2. **이미 판정한 문헌으로 학습시키면 크게 좋아진다** (꼬리 AP 0.47 → 0.80). 개선의 대부분은 임베딩이 아니라 학습에서 왔다.
3. 특허 문헌은 기술 용어가 성능을 좌우해서, 글자 n-그램 특징이 범용 임베딩과 같거나 더 낫다. GPU도 필요 없다.
4. 주의할 점:
   - 라벨이 Codex 판정이므로, 이 수치는 "Codex 판정과의 일치도"다.
   - 학습 점수의 확률값은 보정되지 않았다. 라벨이 상위 구간에 몰려 있어 유효 비율을 과대 추정하므로(미선별 유효 약 1,300건 vs 꼬리 표본 추정 약 740건), **남은 건수 추정에는 꼬리 표본만 쓴다.**

## 결정
- `park rank`에 **판정 학습 모드**를 추가한다 (CPU, scikit-learn).
- 선별은 다음 순환으로 한다: 판정 → 학습 → 미선별 재정렬 → 상위 선별 → 꼬리 표본으로 남은 양 확인. 전자증거 분야의 연속 능동학습(CAL)과 같은 방식이다.
- 임베딩은 꼭 필요할 때만 쓰는 선택 기능으로 둔다. 다음 확인 거리: 임베딩과 n-그램을 함께 쓰면 더 나은지, 판정이 수십 건뿐인 초기에는 어떤지.
